# 벤치마킹 홈 리디자인 — 디자인 스펙

- 날짜: 2026-07-14
- 상태: 사용자 승인 대기
- 대상: `index.html`, `src/app.js`, `src/matrix.js`(신규), `src/cards.js`, `styles/main.css`, `tests/`(계약 재정의)

## 목적 재정의

사이트의 새 정의:

> 교육청·지자체·학교 담당자가 **다른 지역의 학교 e스포츠 대회·정책·시설·동아리 사례**를 근거 자료와 함께 비교·확인하는 벤치마킹 도구.

핵심 대상은 교사·교육청·지자체 담당자다. 핵심 화면은 전국 비교 매트릭스이며, 홈 자체를 매트릭스 히어로로 재구성한다. 기존 사례 탐색(카드 목록 + 상세 + 출처)은 같은 홈 아래에 유지한다.

## 해결하는 문제

1. **'other' 66건 매몰**: `resource_type=other`인 지자체정책·조례 23건, 대학학과·전공·동아리 27건, 언론보도 16건은 현재 유형 버튼(학교/대회/시설)으로 도달 불가능하다. 벤치마킹에 가장 중요한 콘텐츠가 정확히 묻혀 있다.
2. **조망 부재**: "다른 지역은 무엇을 하는가"를 한눈에 볼 화면이 없다. 현재는 지역 하나 + 유형 하나를 골라야만 결과가 보인다.
3. **분류 축 불일치**: 벤치마킹의 의미 있는 축은 카테고리(8종)인데 UI의 1급 축은 유형(3종)이다.

## 1. 새 홈 구조 (index.html, 위→아래)

1. **헤더** — 타이틀·통계 리본 유지. `trust-note`를 목적 문구로 교체: "교육청·지자체·학교 담당자가 다른 지역의 학교 e스포츠 대회·정책·시설·동아리 사례를 근거 자료와 함께 확인할 수 있습니다." 기존 starter-controls(지역 셀렉트 + 유형 버튼 3개)는 헤더에서 제거한다.
2. **비교 매트릭스 패널** (신규, 전폭 히어로) — §2.
3. **탐색 패널 + 지도 패널** — 기존 2컬럼 유지. 지역 셀렉트(`#region-select`)는 탐색 패널의 필터 행으로 이동한다. **"카드 목록(#result-list)이 지도(#region-map)보다 DOM에서 앞" 계약은 유지한다.**

## 2. 비교 매트릭스 (신규 `src/matrix.js`)

### 2.1 모델 (순수 함수, 유닛 테스트 대상)

`matrixModel(entries, regions)` → `{ categories: string[], rows: [{ regionId, regionName, cells: [{ category, count }], total }], columnTotals: [{ category, count }], grandTotal }`

- 로드·검증된 `site.v3.json`에서 런타임 파생. 새 데이터 파일·하드코딩 없음.
- 카테고리 열 순서(고정, 의미 순): 교육청대회·사업 → 지자체정책·조례 → 협회사업 → 학교동아리·팀 → 특성화고학과·과정 → 대학학과·전공·동아리 → 경기장·인프라 → 언론보도. 데이터에 이 목록 밖의 카테고리가 등장하면 뒤에 가나다순으로 자동 추가한다.
- 행 순서: `regions` 배열 순서(시·도 공식 순서) 고정. 정렬 UI 없음.
- 무결성: `grandTotal`은 entries 길이와 같아야 하며(230), 행 합계의 합 = 열 합계의 합 = grandTotal.

### 2.2 렌더 (`renderMatrix(container, model, onSelect)`)

- `<table>` + `<caption>`, thead `th scope="col"`, 행 헤더 `th scope="row"`.
- count>0 셀 = `<button>` (클릭 시 `onSelect({ regionId, category })`), `aria-label` 예: "부산광역시 지자체정책·조례 3건 보기". count=0 셀 = 비활성 텍스트 "·".
- 열 헤더 = 버튼: `onSelect({ category })` (전 지역 해당 카테고리). 행 헤더 = 버튼: `onSelect({ regionId })` (해당 지역 전체). 합계 행/열은 버튼 아님.
- 데이터 로드 실패 시 매트릭스 컨테이너는 렌더하지 않는다(기존 start() catch 경로 — 별도 오류 UI 없음, 탐색 패널의 기존 data-error가 오류를 전달).

### 2.3 윤리 가드레일

- 정렬·순위 기능 없음. 시·도 공식 순서 고정.
- 표 직상단 필수 캐비앗: "공개자료에서 확인한 사례 수이며, 지역의 실제 활동 규모나 순위를 나타내지 않습니다." + research 페이지 링크.

### 2.4 접근성·모바일

- 셀 버튼 등 모든 인터랙티브 컨트롤은 44.5px 플로어 준수(기존 계약).
- 모바일: 매트릭스 컨테이너 `overflow-x: auto` + 첫 열(지역명) sticky. 페이지 본문 가로 스크롤 금지 계약 유지(스크롤은 매트릭스 컨테이너 내부에서만).
- axe serious/critical 0건 유지.

## 3. 필터 체계 재편 (탐색 패널)

- **1급 필터 = 카테고리 칩 8종** (단일 토글, `aria-pressed`, 다시 누르면 해제) + 지역 셀렉트. 칩은 기존 `SET_FILTER("category")` 액션 재사용(단일 토글 = 배열 길이 0/1).
- **유형은 고급 필터로 이동**: 학교/대회/시설/기타 4종 + 전체를 가진 `<select>`. `TYPE_LABELS`에 `other: "기타"` 이미 존재. 이것으로 'other' 66건이 UI에서 도달 가능해진다.
- **게이트 제거**: `readyToBrowse = region && type` 삭제 → 항상 `filterEntries` 실행. 필터가 모두 비면 230건 전체 표시(성능 문제 없음). 결과 카운트 문구는 "230개 항목"이 기본값이 된다.
- 카드 메타 라인에 **연도** 추가(예: "부산광역시 · 대회 · 교육청대회·사업 · 2025").

## 4. 상태 기계·URL

- `state` 구조(필드) 변경 없음. 게이트와 UI 배선만 변경.
- 매트릭스 `onSelect` 후 상태는 **선택한 region/category만 설정되고 나머지 필터(검색어·유형·학교급·상태·범위·정렬)는 비어 있는 상태**여야 한다(기존 액션 조합으로 구현, 새 액션 타입 없음). 이후 탐색 패널(`#results-heading`)로 스크롤·포커스. `prefers-reduced-motion` 시 즉시 점프.
- 카테고리 정식 순서 목록은 `src/matrix.js`가 export하는 단일 상수로 정의하고, 매트릭스 열과 카테고리 칩이 같은 목록을 사용한다.
- `url-codec.js` 변경 없음: `?category=…` 단독, `?type=other`, 지역 없는 URL 모두 기존 코덱이 지원. 기존 공유 URL 전부 그대로 동작.

## 5. 테스트·계약 변경

| 파일 | 변경 |
| --- | --- |
| `tests/fixtures/ac01-tasks.v1.json` | **내용 개정(in-place, `revision: 2` 필드 추가)** — U1-U5를 새 동선("콜드 홈 → 매트릭스 셀 → 카드 → 상세 → 출처 URL sha256 검증")으로 재정의. task의 `type` 필드는 `category`로 교체. 파일명을 유지하는 이유: `pages.yml` human-gate가 이 경로를 하드코딩으로 읽고 Python 워크플로 계약 테스트가 pages.yml을 검증하므로, 파일명 변경은 보호된 워크플로·Python 테스트 수정을 연쇄시킨다. 이전 내용은 git 이력으로 보존된다. `human_approval`은 구현 검수 후 사용자가 기록할 때까지 `pending`으로 되돌린다. |

## 6. 거버넌스 터치포인트

- AC01은 `human_approval` 기록이 있는 인간 승인 계약이다. v2 픽스처는 새 동선 정의이므로 **구현 완료 후 사용자가 직접 새 동선을 검수하고 승인을 기록**해야 한다. 승인 전 상태로는 배포하지 않는다.
- 배포는 기존 절차: 로컬 `verify:release` 통과 → main 푸시 → 소유자 오버라이드 workflow_dispatch.
